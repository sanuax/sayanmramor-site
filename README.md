# sayanmramor-site

Каталог продукции sayanmramor — отдельный статический сайт (без сборки,
без фреймворка), будущий поддомен основного сайта. Дизайн:
`docs/superpowers/specs/2026-09-16-sayanmramor-catalog-site-design.md`.

## Связь с калькулятором — только два контракта

Сайт не загружает код калькулятора (ни JS, ни CSS) и не дублирует его
логику: цена, размеры, форма, кромка и всё остальное считаются только в
конфигураторе. С калькулятором сайт связан ровно двумя контрактами:

1. **Переход в конфигуратор по URL**
   `/sayanmramor-calculator/sayanmramor-calculator.html?product=<product-key>[&stone=<stone-id>]`.
   Ссылку строит `ShowroomData.buildConfiguratorUrl()`
   (`js/showroom/showroom-data.js`) — единственное место на сайте, где
   живут этот путь и 9 публичных product keys.
2. **Данные о камне** — `/sayanmramor-calculator/data/stone-index.json` (и картинки из
   `/sayanmramor-calculator/data/`, на которые он ссылается). `slabs.json` — источник
   истины калькулятора (его читает только калькулятор);
   `stone-index.json` — производный облегчённый индекс для страниц
   категорий, его строит `scripts/build_stone_index.py` калькулятора из
   `slabs.json`: только камни, которые можно заказать, и только поля
   `id`, `name`, `category_label_ru`, `image`.

`tests/site.test.js` проверяет, что страницы не подключают ничего с
`/sayanmramor-calculator/`, что нигде нет `<base>` и что в коде сайта нет других
ссылок на `/sayanmramor-calculator/`, кроме этих двух.

## Локальный запуск

Сайт и калькулятор — два отдельных репозитория, но в браузере они живут
на ОДНОМ origin, как в продакшене. Одна команда (из любой папки):

```
python D:\sayanmramor-site\scripts\dev_server.py
```

Это `scripts/dev_server.py` — маленький dev-сервер на стандартной
библиотеке Python (только для локальной разработки, не часть сайта):

| URL                                | Откуда отдаётся                                        |
|------------------------------------|--------------------------------------------------------|
| `http://localhost:8000/sayanmramor-site/...` | этот репозиторий, `D:\sayanmramor-site`      |
| `http://localhost:8000/sayanmramor-calculator/...`       | актуальный калькулятор — worktree `D:\calculator\.worktrees\rate-catalog-subcategories` |
| `http://localhost:8000/`                     | редирект на главную сайта                    |

Canonical-адрес для QA — `http://localhost:8000/`:

- `http://localhost:8000/sayanmramor-site/index.html` — главная;
- `http://localhost:8000/sayanmramor-site/showroom.html` — 3D-шоурум;
- `http://localhost:8000/sayanmramor-calculator/sayanmramor-calculator.html?product=stoleshnitsa_kuhnya&stone=delicato-brown` — конфигуратор.

`D:\calculator` (основной checkout, ветка `master`) для QA НЕ используется:
в нём нет актуального конфигуратора. Другой checkout калькулятора можно
подставить параметром `--calculator <папка>` (или переменной
`SAYAN_CALCULATOR_ROOT`), порт — `--port`. Сервер отвечает с
`Cache-Control: no-store`, чтобы после правки файла не открывалась
старая версия.

**Если браузер всё ещё показывает старый калькулятор** (он мог
запомнить файлы `D:\calculator` master от прежнего способа запуска):
откройте `http://localhost:8000/` — этот адрес очищает HTTP-кэш сайта
(`Clear-Site-Data`) — и затем откройте калькулятор в новой вкладке
(или Ctrl+Shift+R).

Не используйте для этого `python -m http.server`: он умеет раздавать
только одну папку, и `/sayanmramor-calculator/` тогда оказывается либо 404, либо
`D:\calculator` (master). Пути `/sayanmramor-site/...` и
`/sayanmramor-calculator/...` сайт использует намеренно — это те же адреса, что на
общем хосте; заменять `/sayanmramor-site/` на `/` нельзя.

Открытие файлов напрямую (`file://`) тоже не работает: `fetch()` данных
о камне и ES-модули шоурума требуют http(s).

## Страницы категорий (`categories/*.html`)

Каждая страница — одно из 9 направлений: примеры работ
(`data/portfolio.json`), галерея камня из `stone-index.json` (поиск, фильтр
по типу камня, «Показать ещё») и нижняя панель «Рассчитать в
конфигураторе». Выбранный камень попадает в ссылку как `&stone=<id>`;
без JavaScript ссылка всё равно ведёт в конфигуратор с нужным
`product`. Логика — `js/category-page.js`.

Пути к картинкам в `data/portfolio.json` — корневые абсолютные
(`/sayanmramor-site/assets/portfolio/...`); при замене плейсхолдеров
на настоящие фото сохраняйте эту форму.

Пути вида `/sayanmramor-site/...` и `/sayanmramor-calculator/...` — это
соглашение локального дев-сервера, которое предполагает, что оба
проекта раздаются с одного хоста именно под такими именами. Топология
продакшен-деплоя (реальный поддомен) — отдельный, сознательно
отложенный вопрос (см. раздел «Известные ограничения» в спеке), и
при его решении эту схему путей, вероятно, придётся пересмотреть.

## Шапка и главная

- **Главная — светлая каменная галерея с одним тёмным проёмом**:
  - Палитра только главной (на `.mast, .home-main`, в `:root` её нет; см. «Главная,
    порядок» ниже): светлая основа, тёмный `#1e2320` и травертин `#ece5d8` / `#a8a194`
    для текста на тёмном, verde `#2f5d50` (действие), мягкая пружина `--spring`
    (CSS `linear()`, перелёт 1 %).
  - Шапка главной (`header.mast`, `js/masthead.js`): «САЯНМРАМОР» строго по центру,
    слева «Создать изделие», справа овалы «Изделия +», «Готовые изделия», «Шоурум +»,
    «Контакты»; до 1180 px — один овал «Меню». Овал с «+» — нативный `<details>`
    (без JS открывается сразу); со скриптом он превращается в плоскость светлого
    травертина, которая вырастает из контура самого овала (`clip-path` от его
    прямоугольника до полного размера). Одна плоскость за раз; Esc (фокус
    возвращается на овал), клик снаружи, уход фокуса и ссылка внутри закрывают её.
    «Шоурум +»: кадр дома (грузится только при открытии), «Открыть шоурум», комнаты.
    На телефоне «Меню» — плоскость на весь экран, страница за ней не прокручивается.
    Над светлой секцией шапка становится светлой (плоскость — базальт).
    При «уменьшить движение» плоскость просто появляется.
  - Hero (`section.night-hero`, `js/home-hero.js`): огромный «САЯНМРАМОР», заголовок,
    текст, «Создать изделие» и настоящий слэб калакатты из шоурума
    (`assets/showroom/stone/calacatta-nova-P0585309.webp`, 2,84 × 1,66 м; показан по
    своему контуру, чёрный студийный фон не виден; цветовой баланс — тот же, что в
    шоуруме). При прокрутке сцена удерживается (sticky) и
    управляется одним числом 0…1: знак уходит в шапку и становится её логотипом,
    слэб поднимается с пола, на нём прорисовываются его настоящие размеры
    (2840 × 1660); пока он встаёт, в его середине открывается срез и расширяется до
    краёв — сквозь него видна готовая лестница (фото №200), в каждой точке либо камень,
    либо изделие, без наложения двух картинок (`clip-path`, тонкая светлая кромка и
    тень внутри среза); в конце — «03 3D и стоимость» и «Создать изделие». Фото слэба
    отдаётся через `srcset`: копии 1600 и 2560 px (`assets/home/`, см. `SOURCES.md`),
    исходник 4096 px — только для очень плотных больших экранов. Лежащий слэб — как
    настоящий: цельная плита с четырьмя углами (силуэт по его собственным прямым кромкам,
    чуть внутрь, без сколов и без отсутствующего угла), чуть повёрнута на полу (−6°),
    точка взгляда немного смещена от центра; её толщина — настоящая грань в 3D (3 см в
    масштабе плиты, по нормали к поверхности), которая сама сходит на нет в перспективе,
    пока плита встаёт; на полу, на 3 см ниже поверхности, её мягкая тень; едва заметный
    перепад света к дальнему краю. Фото слэба не изменялось. На телефоне и без сцены
    плита показывается по тому же контуру, без 3D.
    Уже 768 px, при «уменьшить движение» и без JS — та же история неподвижно:
    знак, текст, слэб с размерами, лестница, три шага.
    Отдельной секции «От идеи к изделию» больше нет: её смысл — в hero.
- **Шапка остальных страниц** (пока прежняя; главная — см. выше) — одна строка на всех страницах, кроме шоурума и главной: «Изделия» (компактная

- **Палитра «Базальт и змеевик»** (`:root` в `css/site.css`): известняковый фон

- **Главная, порядок**: hero «из плиты — в изделие» → что можно заказать → портал
  в 3D-шоурум → готовые изделия → расчёт → где мы находимся. «Реальных работ» на главной
  нет: портфолио живёт на страницах направлений.
  Главная светлая (свои значения на `.mast, .home-main`): фон `#f0eee9`, поверхность
  `#f7f5f1`, линии `#d5d1c8`, текст `#1c1d1b`, verde `#2f5d50`. Секции говорят ролями
  (`--ground`, `--figure`, `--figure-soft`, `--rule`…), по умолчанию светлыми; тёмный
  `#1e2320` — только внутри `.night`, то есть у портала в шоурум, и у footer. Двух тёмных
  секций подряд нет. Слэб в hero всегда показан по своему контуру (`clip-path`), чтобы
  чёрный фон студийной фотографии не попадал на известняк:
  - Что можно заказать (`js/home-wall.js`): «Стена» — облицованная стена из 13 каменных
    плит, по одной на направление. Роль блока между hero (материал) и шоурумом

    каждая плита бросает тень в шов), светлая фаска по распилу, свет к полу гаснет, у
    основания стены — её тень; между группами шире шов, название группы — на «полу» под ней.

    курсором, не меняется); плита остаётся открытой, клик открывает страницу; переход — мягкая

    Телефон, планшет, сенсорные экраны и уже 1200 px: та же стена в два ряда по границе
    групп (7 и 6 плит), без открытой плиты; касание сразу открывает страницу.

    направлениях — прежний аккордеон и прежний вид, все новые правила только для

## Шоурум (`showroom.html`)

Интерактивный 3D-дом: фасад, холл, гостиная, кухня, лестница, ванная. На
реальных каменных поверхностях дома — точки; карточка изделия ведёт в
конфигуратор по неизменному контракту
`/sayanmramor-calculator/sayanmramor-calculator.html?product=<product-key>[&stone=<stone-id>]`.
Код калькулятора шоурум не использует — только эту ссылку.

- `js/showroom/showroom-data.js` — направления (9 product keys), зоны дома,
  объекты шоурума (что, где, какой product key, текст карточки), сборка URL.
- `js/showroom/showroom-state.js` — состояние (зона, карточка, «Все
  изделия») как чистый reducer, режим раскладки, fallback без WebGL.
- `js/showroom/house-model.js` — сам дом как данные: участок с оградой
  (каменный цоколь, тёмные металлические ламели, каменные столбы, въезд на
  дорожке), каменные фасады (облицовка — отдельные плиты со швами,
  `claddingSlabs`), входная группа, терраса с ограждением, интерьеры, группы видимости для
  «разреза» комнат, тёплые источники света. Камни дома — один набор:
  собственный светлый известняк (фасады, пояса, ограда, мощение),
  Steel Grey (цоколь, ступени, наружные подоконники, лестница, стена
  холла), Viscont White (кухня), Calacatta Nova (ванная, включая пол),
  Majestic (акцентная стена, bookmatch). Полы в комнатах — светлая
  дубовая доска (процедурная текстура).
- `js/showroom/stone-photos.js` — фотографии камня Venezia Stone
  (`assets/showroom/stone/`, происхождение — `SOURCES.md` там): основные
  фото и конкретные слэбы (партия, пачка, реальный размер, обрезка по
  контуру плиты, баланс цвета) и раскладка участка слэба на поверхность.
- `showroom-scene.js`, `-geometry.js` (фаски, плиты, слияние деталей в
  пакеты), `-materials.js` (процедурный известняк; фото камня грузятся в
  фоне после первого кадра, основные фото сшиваются бесшовно),
  `-camera.js`, `-markers.js`, `-ui.js`, `-app.js` — отрисовка (Three.js
  r160, `vendor/three/`, MIT).

Без WebGL/JavaScript страница показывает статический список всех 9
направлений с теми же ссылками. `showroom.html#kitchen` (и другие зоны)
открывает сразу нужную зону.

## Где мы находимся (главная, `#contacts`)

Одна физическая точка — «Офис продаж и производство», МО, г. Ивантеевка,
ул. Толмачева, д. 80 (данные с sayanmramor.ru; юридический адрес на
Складочной — не место для визита, на карте его нет). Точка и ссылки —
`js/contacts-map.js` (`OFFICE`, `routeUrl`, `openUrl`); координаты —
адресная точка Яндекс Карт для «улица Толмачёва, 80, Ивантеевка».

- Карта: Leaflet 1.9.4 (`vendor/leaflet/`, BSD-2-Clause) и тайлы
  OpenStreetMap, приглушённые под палитру сайта в `css/site.css`.
  Подпись «© OpenStreetMap» обязательна по правилам OSM. Для большого
  трафика тайлы стоит перевести на коммерческого провайдера — это одна
  строка `TILES` в `contacts-map.js`.
- «Построить маршрут» и «Открыть в картах» — обычные ссылки на Яндекс
  Карты; адрес, телефон и ссылки есть в HTML, поэтому работают и без
  карты. Если тайлы не загрузились, в рамке карты — ссылка на Яндекс Карты.
- Мышь: перетаскивание, «+/−», колесо — после клика по карте. Телефон:
  одним пальцем листается страница, двумя — карта; «+/−» работают тапом.
